# 依頼や設計をそのまま信じない（着手前に1回）

設計書や手順書は正本でも、**今も正しいとは限らない**。書かれた後で状況や人の考えが変わっていることがある。依頼の言い方や、人が出した案、前からのやり方も同じで、**前提ではなく材料**として扱う。

着手の前に1回だけ、下の4つの問いを当てる。読み直すたびには回さない（進まなくなる）。

## 1. 4つの問い（各1行で答え、答えの出どころを書く）

1. **古くないか**：その記述が書かれた**後**に、同じ対象の実物・決定・人の発言が動いていないか。ページの更新日ではなく、その節の日付で見る
2. **現実に合うか**：前提にしている件数・分布・使われ方が、実際のデータで成り立つか。印象でなく**数える**
3. **人の考えが変わっていないか**：その後の発言・決定と食い違わないか
4. **もっと良い方法はないか**：達成したいことだけを残して手段を捨て、別の手段を1つ描く（既存の道具やライブラリで済まないかも見る）。元の案が勝つ理由・負ける理由を1行ずつ

依頼が「AかBか」の形で来たときは、その枠を前提にせず、達成したいことだけを残して問い2と4を当てる。CもDもありうる。

## 2. 見つけた差の扱い

| 差 | どうするか |
| --- | --- |
| 差なし | 報告に1行「ゼロから見て、差なし（出どころ）」。止まらない |
| 書き遅れ：実物・データ・決定がすでに答えを決めていて、文書が追いついていないだけ | 止まらない。決まっている側で作り、文書を直すか直す提案を出す |
| 根拠で理想の形が言える（法令・実データ・決定・目的の物差し） | 止まらない。理想の形で作り、依頼との差と根拠を報告に1行。依頼どおりにして辻褄を合わせない |
| 理想の形が大きく変える・高くつく（画面の骨格、データの形、現場の流れが変わる、手間が依頼の規模を大きく超える） | 着手前に止める。案A（理想・おすすめ）と案B（既存寄り）を、差の根拠とそれぞれの手間と一緒に1画面で出す |
| 根拠を引いても優劣が出ない（好みや方針で決まる） | when-to-ask の「どうすべきかが決まっていない」に当たる。形は上と同じで、選ぶのは人 |

## 3. しないこと

- 文書を黙って書き換えない。書き遅れの訂正だけ直し、方針の選び直しは人に回す
- 毎回大がかりに調べない。4つの問いは手元の証拠で答える
- 1回で済ませる

## 4. この作法が見ないもの

- 4つの問いに答えたことは、答えが正しいことを意味しない。特に「数えた」でも母集団を取り違えることがある（grounding の3）
- 文書が無い領域は対象外。そこは疑う前に、まず決める話
