# 長い手順書は、手順を写してから入る

**手順が5つ以上ある文書に従うときは、手順の見出しを一字一句そのまま作業リスト（TODO）に写してから始める。** 飛ばすときは行を消さず、`skip: 理由` を残す。

```
1. 対象を決める                         ✔
2. 先に同じものが無いか探す              ✔
3. 依存を用意する                        skip: 依存を変えない作業なので要らない
4. 結果を見比べる                        ← いまここ
5. 報告する
```

## なぜ

途中の小さな論点を片付けているうちに、**元の目的を見失う**。手順が「在る」ことと、手順を「通った印が在る」ことは別物で、印が無い手順は飛ばしても黙って通る。

## 守ること

- **そのまま写す。** 要約すると写した側の解釈が混ざり、元の手順と突き合わせられなくなる
- **飛ばした行を消さない。** 消すと「やった」と「要らなかった」が区別できない
- **理由は1行で、何を見てそう決めたかを含める。**「不要」だけでは足りない
- **終わりに `skip` の行だけ読み返す。** 飛ばした判断がまだ正しいかを1回だけ見る
- **報告に `skip` の数と、そのうち意味が大きいものを1行**（0件なら書かない）

## この作法が見ないもの

- 機械では測っていない。守るのは自分の規律
- 手順書そのものが古いときは助けにならない（書いてあることを忠実に通るだけ）。それは premise-doubt の側
- 1行に作業が5つ詰まっていれば、写しても1行のまま
