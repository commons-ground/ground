# 決定の記録（ADR）の書き方

ADR は年単位で読み返す文書。**決めたことと、その理由だけ**を置く。短期間で変わる情報（進捗、件数、実装の細部）を置くと、本文のほうが先に嘘になる。

規約には強さが2つある。**MUST**（満たす）と **SHOULD**（原則満たす。外すなら理由を1行書ける）。レビューでは「B-2 に反している」の形で短く指す。

雛形は [references/template.md](references/template.md)。

## A. 節の名前と並び

名前が揺れると検索で引けず、読む人は毎回どこに何があるか探し直す。

| ID | 強さ | 規約 |
| --- | --- | --- |
| A-1 | MUST | 節名は下の表から選ぶ。言い換えない・括弧で飾らない |
| A-2 | MUST | 先頭に `- 状態:`（提案・採用・置き換え済み・取り消し と日付） |
| A-3 | SHOULD | 「この ADR で決めないこと」を置き、**任せる先を名指しする** |

| 節 | 要るか | 中身 |
| --- | --- | --- |
| `## 何を決めたか` | MUST | 決めたことだけ |
| `## なぜ` | MUST | そのリポジトリで実際に起きたこと（C-2） |
| `## この ADR で決めないこと` | SHOULD | 任せる先を名指し。無いなら「決まっていない」と課題の番号 |
| `## 強制箇所` | hook があるとき MUST | hook のファイル名と、どのイベントで効くか。止めたときの文の `REF:` がここを指す |
| `## FIX（正しいやり方）` | 止めるとき MUST | 止められた側がどうすれば進めるか |
| `## 検討して採らなかった案` | MUST | 無ければ「検討していない」と1行 |
| `## 限界` | MUST | この決定で取れないもの。作った以上、書く |

既存の ADR を一括で書き換えない。次にその ADR に触るときに寄せる（一括の置き換えは、いつ決まったかを履歴から引けなくする）。

## B. 書かないもの

| ID | 強さ | 規約 |
| --- | --- | --- |
| B-1 | MUST | 進捗・チェックボックス・残作業の表を書かない。決めたのが「順序」なら順序は書いてよい。書かないのは「どこまで済んだか」 |
| B-2 | MUST | 実装の細部を決定の文に書かない |
| B-3 | MUST | すぐ古くなる数え上げを、日付なしの現在形で書かない。実測の表は根拠の文書（rationale）に置き、ADR からは `REF:` で指す。「〇年〇月〇日時点で N 本」のように日付を添えた1行はよい |

B-2 の判定の問い：**決めた方式を別の形に置き換えたとき、ADR の本文を書き換える必要があるか。** 要るなら、その記述はプルリクエストか仕様書に属する。

- だめ：「判定は `send()` に置く。環境変数をカンマで区切って読み、小文字にしてから照合する」
- よい：「許可した宛先以外へは送らない。設定が無いときは送らない側に倒す。判定は送信の出口1か所に置く」

## C. 確かめた事実で書く

| ID | 強さ | 規約 |
| --- | --- | --- |
| C-1 | MUST | 事実は、その作業で自分が開いた一次資料で確かめ、出どころ（ファイルの場所か URL）を書く（core の grounding の4） |
| C-2 | MUST | 「〜すると〜になる」の一般論で済ませない。「いま〜になっている」と、起きていることを書く |
| C-3 | MUST | ほかの ADR を指すときは「ADR-NNN の『節名』」の形。行番号や「上の方」で指さない |

C-2 の例：

- だめ：「秘密でない設定値まで同じ保管場所に置くと、区別とレビューが不明瞭になる」
- よい：「いま接続先の URL が秘密の値と同じ保管場所に入っている（`config/services.php:12`）。そこは差分のレビューに出ないので、URL を1文字変えても誰も気づかない」

会議で確かめた・口で聞いた、は確かめたことにならない。その場にいなかった人と半年後の自分が検証できない。会議が出どころなら、議事録の場所と逐語を書く。

## D. 置き場と置き換え

- 装置（hook・規則・自律の線）の決定と、アプリの構造（表・鍵・移行）の決定は、置き場を分ける。混ぜると、どちらを探す人も両方を読むことになる
- 決定を変えるときは、古い ADR を書き換えず、新しい ADR を作って古い方を「置き換え済み（ADR-NNN へ）」にする。理由の履歴が残る

## E. 例の書き方

- 例は「だめ／よい」を並べ、どこが違うかが一目で分かる短さにする
- 実データ（人名・金額・取引先・URL・ID）を例に使わない。架空の値にする

## この規約が見ないもの

- 決定の中身が正しいかは見ない。形の規約
- 節名がそろっていても、「なぜ」が後付けの理屈なら見抜けない。C-2 の「いま起きていること」を求めるのはそのため
