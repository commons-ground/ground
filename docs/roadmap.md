# コモンズのロードマップ

コモンズの仕組み（スキル、Discord・GitHub・Notion とのつなぎ口、守り）を、これからどう育てるかの道筋。

- **進み具合の正本**：ground の Issue（ラベル「ロードマップ」）。PR に `Closes #番号` と書けば、マージで自動で閉じる → https://github.com/commons-ground/ground/issues?q=label%3Aロードマップ
- **この文書**：方針と段階だけを書く。細かい進み具合は Issue を見る
- **見直し**：月1回、試行の棚卸しと同じ場で（次は 2027年1月中旬の「棚卸しの会」）
- 版：v2.0（2026-11-25）

## いまどこにいるか

**トライアル期の「動くものをそろえる」段階が終わり、「数を減らす・期限で止まらない・壊されにくくする」段階に入ったところ。**

2026年11月24〜25日で、Discord の `/ai`・`@コモンズのAI`、通話の `/record` と議事録、`#提案` と篩（ふるい）、分身の AI、GitHub の `@claude`、コネクタからの Discord の読み書きがそろった。ほとんどが「試行」として入っていて、見直しは1月の棚卸しの会でまとめて行う（[試行一覧](trials.md)）。

## 段階

### 今：門を閉じる・止まらない（2026年11月）

- 自動で入る変更のうち、鍵を持って動く仕組み（workflow・tools・コネクタのサーバー）と、AI のふるまい・覚えていることは「人の確認」を通す
- 期限のある鍵を、期限の無い仕組み（GitHub アプリの鍵）に置き換える
- Worker の置き直しを、GitHub の手動の実行でできるようにする
- 公開の場（Issue・試行一覧）に人の名前を書かない

### 次：数を減らす・自動で気づく（2026年12月）

- 期限切れや止まった PR を、すでにある毎分の見回りが1日1回点検し、異常のときだけ知らせる
- Discord の受け口を中継に吸収し、Discord の玄関を1つにする
- 入口を「入るのは軽く、書けるのは一段あと」にする：Discord に入れば `/ai` を試せる。Notion への書き込みと `#提案` は「参加者」ロールで開く
- 「取り下げ」の一言で、試行を戻す PR を出せるようにする
- 使われた記録（スキル名と 👍👎 の数だけ）を残し、試行の判断の材料にする

### その後：壊されにくくする（2027年1月〜）

- 棚卸しの会で、11月の試行の定着・延長・取り下げを決める
- Worker の置き直しを、人の確認つきで GitHub から行う
- 世話役を2人にする（GitHub の団体・Discord・Cloudflare）
- 知識コモンズ（Notion）を毎月書き出す
- 2つ目のコモンズを作るときに、コモンズを表す設定の型を抜き出す

## 決めた方針

- **共有スキルの置き場は GitHub だけ。** 人が探すときは [スキルの一覧](https://commons-ground.github.io/ground/skills.html)。新しいデータベースは作らない
- **Notion は、知識コモンズと「人が直す場所」に使う。** 各自・個別のコモンズのスキルは、既定で Notion のスキル表に置く
- **リポジトリは公開のまま。** 守るのは「秘密」より「壊されないこと」。外に出したくないノウハウが入り始めたら、公開の ground と非公開の各コモンズに分けることを考える
- **AI の動かし方は入口で分ける。** GitHub から起きるものは公式の Claude Code Action、Discord から起きるものは自作の runner
- **家族のコモンズ（川野家）の仕組みは、コモンズの中継に寄せない。** コードは共有し、置き場は分ける（補完性原理）
